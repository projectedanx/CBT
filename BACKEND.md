# BACKEND MIGRATION SPECIFICATION // FIREBASE

## Overview
Currently, the application relies on `localStorage` for persistence. To enable cross-device synchronization, collaborative features, and vector-based discovery, we will migrate to a Serverless Firebase architecture.

## 1. Authentication
*   **Provider:** Firebase Auth.
*   **Methods:**
    *   `Anonymous` (Default entry).
    *   `Google Sign-In` (Upgrade path to preserve history).
*   **Logic:** On upgrade, merge `localStorage` history into the Firestore `users/{uid}/history` collection.

## 2. Firestore Schema

### Collection: `users`
User-specific preferences and aggregate stats.
```json
{
  "uid": "string",
  "displayName": "string",
  "createdAt": "timestamp",
  "stats": {
    "totalBlends": "number",
    "savedArtifacts": "number"
  }
}
```

### Collection: `blends` (Global Ledger)
Stores unique blends generated by the system.
```json
{
  "id": "auto-generated",
  "creatorUid": "string",
  "timestamp": "timestamp",
  "inputs": {
    "conceptA": "string (lowercase)",
    "conceptB": "string (lowercase)"
  },
  "genericSpace": {
    "structure": ["string"],
    "similarity": "number"
  },
  "result": {
    "name": "string",
    "description": "string",
    "mechanics": "string"
  },
  "meta": {
    "model": "gemini-2.5-flash",
    "temperature": 0.8
  },
  "public": "boolean" // Default false
}
```

### Sub-Collection: `users/{uid}/history`
References to blends created by the user, plus their specific context.
```json
{
  "blendId": "ref",
  "timestamp": "timestamp",
  "userRating": "like" | "dislike" | null,
  "isSaved": "boolean"
}
```

## 3. Cloud Functions (API Security)
Currently, the API Key is client-side. This is acceptable for a Sovereign Applet but insecure for production.

**Function: `generateBlend`**
*   **Trigger:** HTTPS Callable.
*   **Input:** `{ conceptA, conceptB, type }`
*   **Process:**
    1.  Validate User Auth.
    2.  Check Rate Limits (Firestore Token Bucket).
    3.  Call Gemini API (Secret Manager stores API Key).
    4.  Write result to `blends` collection.
    5.  Return result to client.

## 4. Vector Embedding Strategy (Future)
To allow users to find "Similar Blends":
1.  On `blends.onCreate`, trigger a Cloud Function.
2.  Generate an embedding for the `description` + `mechanics` using `text-embedding-004`.
3.  Store in a dedicated Vector Store (e.g., Pinecone or Firestore Vector Search extension).
